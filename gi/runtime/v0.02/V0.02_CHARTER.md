# GI Runtime Kernel v0.02 — Development Charter

Status: DEVELOPMENT
Parent: GI Runtime Kernel v0.01 FROZEN
Rule: v0.01 remains immutable. All new changes occur only in v0.02.

## Purpose

GI Runtime Kernel v0.02 moves beyond proving that the runtime loop exists. Its purpose is to test whether the kernel can support richer, dynamically generated structure without hard-coding fixed primitive counts, fixed graph shape, fixed candidate sets, or fixed computational roles.

The central question is:

Can the runtime reorganize its own computational structure while preserving the invariants already frozen in v0.01?

## v0.02 Minimum Research Targets

1. Dynamic primitive population: allow primitives to be created, merged, retired, or reactivated. Primitive count N becomes runtime state rather than a permanently fixed constant.
2. Dynamic topology: permit causal edge creation/removal/reweighting/delay changes during execution; topology mutation must remain attributable and testable.
3. Adaptive role formation: primitives must not be assigned semantic identities; computational roles should emerge from state, topology, history, persistent condition, and repeated interaction.
4. Structural conservation/admissibility: reorganization must preserve causal traceability, bounded state, determinism under fixed conditions, checkpointability, and unresolved-state preservation.
5. Noetican continuity across structural change: Groups 1–3 must continue to operate when primitive count/topology changes; operative representation and consequence resolution cannot depend on static indexing.

## Boundary

v0.02 does not claim autonomous learning, semantic understanding, AGI, or self-directed architecture search. It tests adaptive computational structure.
